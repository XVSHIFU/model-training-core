# 开源训练方法调研与硬件预算

调研日期：2026-09-28。本文选取资料充分的代表版本，非最新模型排名。官方披露、工程预算和本项目实测分开记录；阅读训练报告不等于复现训练。

## 1. 当前项目是什么

当前已实现 TF-IDF + 可选数值特征 + Logistic / LightGBM 分类。它能复用数据检查、训练、预测、评测和产物追溯流程，但尚未实现语言生成、视觉或神经网络微调。

这里要提炼的是可跨任务使用的训练工程方法。不存在把所有数据放入同一个算法、就能训练语言和视觉能力的万能模型。不同任务共享流程，各自选择表示方法、模型、损失函数和评测。

## 3. 抽象成一套通用训练逻辑

1. **定义任务和验收**：输入是什么、输出是什么、怎样算正确、错误代价多大。先确定指标与基线。
2. **建立数据契约**：保存来源、许可、标注规则、用途、版本和分组；先分训练/开发/测试，再做只基于训练集拟合的处理。
3. **选择表示与底座**：稀疏特征、文本 tokenizer、图像处理器分别属于不同后端；固定底座与预处理器版本。
4. **确定学习目标**：分类、下一 token 预测、监督指令学习、偏好学习或自监督表示学习。目标必须与数据格式相符。
5. **确定参数更新方式**：全参数更新、冻结编码器只训练头、LoRA，或量化底座上的 QLoRA。
6. **先做小规模试跑**：检查损失、样本与标签对应、梯度和显存；确认能够保存、恢复、加载预测，再扩量。
7. **固定条件做对照**：未训练底座、简单基线、新模型在同一开发集比较；最终版本再使用未参与选型的测试集。
8. **交付完整产物**：权重/适配器、底座引用、处理器、配置、环境、数据指纹、评测与资源开销共同组成制品。

SFT 是“用示范答案学习”的目标/阶段；LoRA 是“更新哪些参数”的方法，二者可以组合。DPO 等偏好方法需要偏好对；强化学习还需要奖励设计和生成采样。不是每个模型都必须依次经过 SFT、DPO、RL。

| 路线 | 数据的基本形式 | 第一版适合验证什么 |
| --- | --- | --- |
| 当前分类模型 | 输入文本/数值 + 类别标签 | 数据隔离、训练预测、分类指标与错误样本 |
| 语言 SFT | 指令或多轮消息 + 期望回答 | 输出格式、任务正确率、对未见输入的表现 |
| 偏好学习 | 同一输入 + 较好回答 + 较差回答 | 偏好是否改善，同时检查原能力退化 |
| 图像分类迁移 | 图像 + 类别标签 | 冻结编码器与轻量分类头的基线 |
| 自监督预训练 | 大量文本或图像；监督信号由目标构造 | 表示与泛化能力，数据规模和算力开销 |

没有具体业务场景也可以用公开教学数据验证流程；合成数据只用于工程检查。真实效果评估最终仍需代表目标分布的独立数据。

## 4. 硬件怎么估算

下面是**首次实验的工程预算区间，不是官方最低要求，也不是本仓库实测结果**。语言 QLoRA 行假设：稠密模型、4-bit 底座、约 1K–2K token、单设备 micro-batch 1、启用梯度检查点，并使用兼容的训练栈。更长输入、更大批量、较大词表、不同实现会改变开销。

| 实验 | GPU 显存预算 | 主机内存预算 | 磁盘预留建议，不含大型原始数据集 |
| --- | --- | --- | --- |
| 当前 TF-IDF + Logistic / LightGBM | 不需要 GPU | 小示例 8GB；常规起点 16GB，扩量可考虑 32GB | 10–30GB |
| 0.5B–3B 语言模型 QLoRA | 8–16GB，按具体模型验证 | 16–32GB | 50–100GB |
| 7B–8B 语言模型 QLoRA | 16–24GB，24GB 留有更多余量 | 32–64GB | 100–200GB |
| 14B 语言模型 QLoRA | 24–48GB | 64GB 起 | 200GB 起 |
| 小型预训练图像分类网络迁移，约 224px | 8–16GB 通常便于试验；极小实验也可 CPU | 16–32GB | 30–100GB |
| 7B 及以上全参数微调 | 需按优化器、序列、分片和卸载方案单独测算，通常考虑高显存或多卡服务器 | 依据分片/卸载与数据流水线预算 | 多份检查点会显著增加空间 |
| 从零训练具备实用通用能力的大语言/视觉底座 | 集群级项目，按 token/图像总量和完成期限规划 | 与集群方案一起设计 | 数据、缓存和检查点需单独规划 |

B 表示十亿参数。表中的主机内存不能代替显存；多卡显存也不会自动拼成一块，必须有模型/状态分片等支持。小型图像分类预算不适用于图像生成、视频模型或大型视觉语言模型。

### 为什么不能只看参数量

训练还要存梯度、优化器状态、中间激活和临时缓冲；量化权重的文件大小不能直接当训练显存。[Hugging Face 显存说明](https://huggingface.co/docs/transformers/main/en/model_memory_anatomy)解释了这些组成部分。

例如，7B 参数的 4-bit 权重仅按位数换算约 3.5GB，但这没有计入量化元数据、未量化层、适配器、激活和训练状态，不能据此说 4GB 显卡可完成 QLoRA。

官方公开配置说明了“微调”和“复现完整训练”的差别：

- [SmolLM3 后训练配方](https://github.com/huggingface/alignment-handbook/blob/main/recipes/smollm3/README.md)声明其全模型训练配置在 **8 张、每张 80GB 显存的 GPU** 上测试。这不是 3B 模型做 LoRA 的最低要求。
- [SmolLM3 基座模型卡](https://huggingface.co/HuggingFaceTB/SmolLM3-3B-Base)披露预训练使用 **384 张 H100**。不能将其预训练成本等同于下载后微调的成本。
- [DINOv2 训练示例](https://github.com/facebookresearch/dinov2#training)中的 ViT-L/16 ImageNet-1k 方案使用 **32 张 A100 80GB**。复用其编码器做分类头训练无需照搬这一配置。

### 购买或租用之前的验收

先固定模型版本、训练方法、输入长度/图像尺寸、精度、micro-batch 和有效 batch；在目标环境试跑约 100 步，覆盖较长样本，并执行一次评测、保存和恢复。记录 GPU 峰值已分配/保留显存、主机峰值内存、tokens/s 或 samples/s、磁盘增量。然后按训练总量估算时间，另计评测、保存与启动开销。

梯度累积能减小一次处理的批量，不能消除单条超长输入的激活占用。不同显卡即使显存相同，吞吐、精度支持和训练库兼容性也可能不同。预算表只负责缩小候选范围，试跑结果决定最终配置。

## 5. 对本项目的落地建议

**现在：**保留 CPU 分类基线，用现有设备运行和改进数据/评测流程。原始业务数据全量重训的峰值内存尚未在本轮测量，不保证任意数据规模都适合 16GB。

**下一阶段：**选一个公开教学任务和一个小型底座，添加独立的语言 SFT + QLoRA 后端；先使用短期 GPU 环境验证，不以采购硬件作为启动条件。视觉路线另做“冻结编码器 + 分类头”示例，比较哪些接口可以共享。

**核心层拟扩展：**模型与处理器 revision、训练阶段、输入制品、数据配方、损失配置、参数更新方式、精度、序列长度、检查点恢复信息、资源测量和评测类型。现有用途隔离、运行状态和产物追溯可以复用；当前样本与评测协议仍需验证能否承载多轮文本和图像。

**后端层拟扩展：**语言后端调用成熟训练工具，视觉后端处理图像增强与编码器；各自锁定可复现依赖环境。不要将其全部塞进当前 SparseClassifier，也不直接将外部仓库的历史依赖装进现有环境。

本轮仅完成资料核对和方案整理，没有安装深度学习训练栈、下载大型权重、训练语言/视觉模型，也没有产生新的硬件性能基准。

# 小模型反馈循环：CPU 实验计划

日期：2026-09-28。状态：设计，尚未实现或跑出结果。保留现有架构，替代先从大语言模型微调入手的优先顺序。

## 目标和边界

在最多 32GB 主机内存、不依赖独立显卡的条件下，验证：共享底座 B0 → 任务小模型 → 经核实的反馈 → 候选底座 B1 → 新任务与旧任务对照评测。

现有 training_core 是工程框架，没有可被反向传播更新的共享神经网络参数。实验新增一个很小的共享编码器作为教学底座；框架按实验发现修正接口，底座按训练信号更新参数。这是两个独立的版本维度。

这套实验验证机制，不宣称获得通用语言、通用视觉或跨模态能力。小模型的准确率只用于选择候选；更新底座需要样本、可靠目标和明确的损失函数，不能只输入一个分数。

## 最小实验

使用 sklearn 自带 digits 数据：8×8 灰度手写数字。无需准备业务数据或下载大模型。先划分样本，再生成任务标签；相同原图及其变体跨任务保持同一分区，完全相同图像归在一起。该数据规模小、任务相关，不能据此证明跨领域迁移。

- 共享编码器：64 → 32 → 16 的小型全连接网络，约 2,600 个参数。
- 初始底座 B0：只用训练分区做图像重建预训练，配一个 16 → 32 → 64 解码器；下游任务使用编码器。
- 任务 A：识别数字 0–9；任务 B：判断奇偶。二者分别在冻结 B0 上训练轻量分类头。
- 任务 C：判断数字是否大于等于 5，作为底座冻结后才运行的迁移探针；C 不参与 B1 更新和选择。
- 保留原像素 Logistic 分类、随机编码器 + 分类头作为便宜基线。

拟采用成熟自动求导工具实现网络，放入可选实验依赖；不修改原 SparseClassifier，不替换现有 CLI。先在 experiments/ 下验证，确认接口需求后再接 TaskAdapter。基础安装仍可独立运行。

## 反馈怎么回到底座

第一版优先使用真实标签反馈：开发集错误分析确定问题类型，在训练池中选择相应样本，用 A/B 监督损失更新共享编码器，同时混合旧训练样本或保留重建目标。开发样本不直接拿来训练，最终测试集不参与错误挖掘。

这相当于由任务反馈引导的多任务继续训练。若后续要直接利用小模型的预测分布，再单独加入蒸馏实验；伪标签不自动当真值，预测分布还必须与对应任务分类头匹配。不直接平均不同任务模型的权重。

底座每次更新生成新候选 B1，B0 和已发布小模型保持冻结；不自动给旧小模型换底座。

## 对照设计与验收

1. 固定训练/开发/最终测试分区；按数字类别分层并检查重复。预先固定三个训练随机种子，各实验使用对应相同种子和相同样本预算。
2. 保存 B0，在 A/B 上训练分类头，记录开发集 macro-F1、准确率、各类错误、耗时、峰值进程内存、制品大小。
3. 比较三种更新：不更新 B0；相同训练步数的普通继续训练；相同预算的反馈定向训练。这样区分反馈效果与单纯多训练的效果。
4. 对每个候选同时检查：旧头保持不变时是否退化；重新初始化并按相同预算训练新头时是否更容易学习。两种结果分别报告。
5. 提前约定开发集晋级条件：A/B 平均 macro-F1 提升至少 1 个百分点，任一旧任务下降不超过 1 个百分点；报告三个种子的均值和离散程度。这只是本试验门槛，不是通用统计显著性标准。
6. 冻结候选后，在 B0/B1 上各自用相同 C 训练样本量和训练预算拟合 C 头，再执行最终测试比较。C 是高度相关的迁移探针，不是未见领域证明。
7. 如果测试结果导致修改方案，相关测试结果从此按历史回归处理；下一次独立声明需要新的保留数据。

验收分两层：保存/恢复一致、血缘可追溯、无泄漏、资源受控表示工程通过；只有受控对照改善且旧任务未明显退化，才表示本次底座改进有证据。没有提升也应保留报告，不强行晋级。

## 预算和交付

CPU 顺序执行，不并行堆多个训练任务。初始 batch 32、最多 50 个 epoch，先做 5 个 epoch 的资源试跑；开发集早停规则在正式比较前固定。总内存 32GB 是上限，不假定本机已升级到 32GB。训练进程以不超过 4GB 为初始目标，实际峰值与耗时由试跑确认，给系统和其他应用保留空间。

交付：实验入口、固定配置和分区记录、B0/B1 制品及父子关系、任务头、预测与错误样本、对照表、资源报告。正式接入前验证冻结参数未变化、保存重载输出一致、分区继承正确，并回归现有工程。

第一轮先完成一个可解释的循环，再考虑换成小型文本编码器或图像卷积编码器；跨模态首先复用流程，不默认复用同一套权重。
